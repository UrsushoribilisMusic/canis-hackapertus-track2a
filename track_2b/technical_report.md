## 1. Summary

Canis is an inspectability layer for AI answers. It runs an Apertus-backed
assistant behind a browser demo and returns both the answer and a compact
disposition readout that indicates whether the model appears confident, unsure,
curious, concerned, reluctant, warm, or neutral. The current Docker prototype
keeps the UI/API contract stable, supports a deterministic mock path for quick
review, and includes an Apertus 8B runtime path for real generation.

## 2. Architecture

Components, data flow, and where each one runs. Put diagrams in `docs/` and
reference them here.

The prototype has three parts:

- Browser UI served from `src/web/`.
- FastAPI backend in `src/backend/app.py` exposing `/api/health`, `/api/models`,
  `/api/chat`, and `/api/disposition`.
- Runtime layer in `src/backend/runtime.py` that selects either deterministic
  mock mode or the Transformers-backed Apertus mode.

The browser sends prompts to `/api/chat`. The backend returns an answer plus a
Canis readout. In mock mode, both the answer and readout are deterministic. In
real-model mode, the answer is generated by `swiss-ai/Apertus-v1.5-8B`; Canis
then attempts a hidden-state forward-lens readout with compact disposition
directions and falls back to the lexical readout only if hidden states/logits
are unavailable.

### Target architecture (mandatory)

Canis targets **a) On-premise**. The submission runs through Docker on hardware
controlled by the deploying organization. The default `make run` path builds
and starts the browser/API prototype without external inference services.

External dependencies:

- Build time: Docker base images and Python packages.
- First real-model setup: authorized Hugging Face access to
  `swiss-ai/Apertus-v1.5-8B` and Swiss AI's pinned Transformers branch.
- Runtime in mock mode: no hosted API dependency.
- Runtime in real-model mode: local model files mounted from the host Hugging
  Face cache; no hosted inference API.

## 3. Use of Apertus

- **Model:** `swiss-ai/Apertus-v1.5-8B`
- **How it is used:** inference and model-state inspection for the Canis
  disposition readout.
- **Where it runs:** local weights inside Docker, with the host Hugging Face
  cache mounted into the container for the real-model path.

The real-model path uses Swiss AI's Transformers branch because the released
Transformers package does not yet support the Apertus 1.5 architecture. The
current generation prompt asks Canis to answer in no more than two short,
complete sentences to keep Docker latency manageable.

## 4. Data

No dataset is bundled with this prototype. The `data/` directory is present for
template compliance and remains empty except for `.gitkeep`. Model weights and
Hugging Face cache files are intentionally excluded from the repository.

The browser supports user-provided sources. PDF, Markdown, and text files are
uploaded to the Docker backend, chunked locally, retrieved by lexical overlap,
and passed to the model as cited snippets. This keeps private documents inside
the local deployment and avoids sending entire files into a prompt.

## 5. Evaluation

How you measured success: task, metric, baseline.

| Setup    | Metric | Result |
|----------|--------|--------|
| Mock runtime | Unit tests | `make test` exercises the disposition resolver, source chunking, and mock answers |
| Apertus 8B probe | Tensor access | Prior local probe exposed logits, hidden states, final hidden shape, and output embeddings |
| Forward-lens artifact | Unit tests | Compact hidden directions produce a `forwardLens` web readout |
| Real-model smoke | Generation | Prior local smoke returned `Hello, Canis.` with a low token cap |

## 6. Limitations

- The real Apertus 8B path is slow on the local Mac Mini Docker CPU/offload
  setup.
- The hidden-state readout depends on the active Transformers model exposing
  hidden states and logits. If that contract changes, the backend falls back to
  lexical scoring rather than failing the answer.
- The browser bundle is prebuilt; rebuilding the Angular app is documented but
  not required for `make run`.

## 7. Reproducibility

What a judge needs to get your numbers back: hardware, runtime, seeds, and the
